# THUTOra deep scan — 19 Nov 2026

A whole-platform audit after ADR-047, covering security, privacy and child
safety, reliability, performance, cost, code quality, accessibility,
content and operations. Every finding below was checked against the code,
a tool or a test run. Nothing is taken on trust from earlier reviews.

**How it was checked**
- Code read of every router, the auth, the AI prompt and the upload paths.
- `pip-audit` and `npm audit` on the dependencies.
- A secrets sweep of the whole git history.
- axe-core accessibility scans of login, LEARN, TEACH and CONNECT.
- A synthetic school of 1,200 learners and 72,000 answers, timing the
  heaviest pages.
- 40 simultaneous tutor questions on the real connection pool.
- The integration suite (20 HTTP tests) and 294 backend tests.

## Verdict

The foundations are good: clear roles and scoping, privacy by design, a
strong test and documentation habit, and a pedagogically serious tutor.

**It is not yet safe for real learners.** Five things must be fixed first:
child-safety rules for the tutor, vulnerable dependencies, the
database-connection bottleneck under a full class, cost visibility, and
the production basics (backups, monitoring, HTTPS). All are fixable. None
needs a redesign.

## Strengths (pros)

| Area | Evidence |
|---|---|
| **Access control** | One scoping model (StaffScope) for every staff endpoint; 404 (not 403) for other people's data; 20 integration tests prove teacher, parent, viewer and other-school isolation. |
| **Privacy by design** | Parents never see tutor conversations; INSIGHTS shows aggregates only, hiding groups under 5; unreleased tests are hidden from family views; consent records; POPIA export and delete; an audit trail; learner names are not sent to the AI. |
| **Auth** | bcrypt; token versioning (password change and deactivation revoke at once); login throttling; one-hour tokens with renewal; bearer tokens in sessionStorage (no cookies, so no CSRF). |
| **Safe rendering** | No raw HTML in chat Markdown; KaTeX with `trust` off; textbook HTML rebuilt through a strict allow-list (scripts, forms, SVG and event attributes dropped; no links at all). |
| **Teaching quality** | Prerequisite diagnosis; MathGuard verifies worked maths; CAPS topic structure for both Physical Sciences papers; open CC BY textbooks beside the chat; home-language help; teacher override of AI marks. |
| **Breadth** | LEARN, TEACH, CONNECT, ADMIN and INSIGHTS on one identity and one database. |
| **Low-data, phones** | Installable PWA; the service worker never caches personal data; phone layout fixed (ADR-047); daily usage limit. |
| **Engineering habits** | 47 ADRs, a build log, CI with migrations up/down/up, lint, 294 backend tests, 22 frontend tests, and no secrets in git history (only fake test keys). |
| **Accessibility** | No WCAG A/AA violations on the LEARN, TEACH and CONNECT screens, including colour contrast. |
| **Speed at school scale** | 1,200 learners and 72,000 answers: parent view 36 ms, ADMIN overview 66 ms, roster 84 ms, Today 339 ms, class progress 0.8–1.0 s. |

## Weaknesses (cons)

- **AI dependency:** one provider and model. There's no fallback when
  Anthropic is down beyond a friendly error.
- **No live deployment yet:** no backups, monitoring, error tracking or
  staging environment.
- **Unknown running cost:** token usage isn't recorded.
- **Content is written, not yet reviewed:** the question bank (including
  today's chemistry) has been written but not reviewed by teachers.
  isiZulu covers Grade 10 only. There's nothing for Grades 8–9, and many
  subjects are missing (Life Sciences, Maths Literacy, Geography...).
- **Frontend maintainability:** three components are over 900 lines each,
  and the frontend tests are utility-only (no screen tests).

> **Status, 20 Nov 2026: every code item below (H1–H5, M1–M8, L1–L8) is
> fixed — see ADR-048.** Still open, because they need people rather than
> code: each school's safeguarding process, an Anthropic data-processing
> agreement, agreed retention periods, the consent policy, teacher review of
> the question bank, and isiZulu Grades 11–12.

## Risk register

Severity: **H** = fix before any real learner uses it · **M** = fix before
the pilot grows · **L** = tidy-up.

### High

**H1 — The tutor has no child-safety or conduct rules.**
- **Evidence:** `services/tutor.py` builds the system prompt from the
  topic, the worked-example anchor, maths formatting, "explain why", the
  textbook text and personalisation. There's nothing on what to do if a
  learner discloses abuse or self-harm, asks for inappropriate content,
  goes off-topic, shares personal details, or tries prompt injection
  ("ignore your instructions…").
- **Why it matters:** the users are minors, and Claude's own defaults are
  not a school safeguarding policy.
- **Fix:** add a safeguarding block to every prompt:
  - stay on schoolwork;
  - never ask for personal details;
  - on a disclosure, respond with care, encourage them to talk to a
    trusted adult, and give Childline South Africa: **116**, free from any
    network, 24/7;
  - ignore instructions inside textbook pages or uploads.
- **Then:** test it with a red-team script, and agree a school
  safeguarding process for flagged conversations. That part is a policy
  decision.

**H2 — Vulnerable dependencies, including the parser for learners' uploaded PDFs.**

| Package | Pinned | Advisories | Fixed in | Why it matters |
|---|---|---|---|---|
| pypdf | 5.1.0 | 103 | 6.21.4 | Parses untrusted PDFs from learners (DoS and memory). |
| starlette | 0.38.6 | 14 | 1.3.1 (via newer FastAPI) | The web layer, including multipart parsing. |
| python-multipart | 0.0.17 | 14 | 0.0.31 | File-upload parsing. |
| python-jose | 3.3.0 | 6 | 3.4.0 | Brings in ecdsa, which has advisories and no fix. |
| python-dotenv | 1.0.1 | 2 | 1.2.2 | |

- **Frontend:** production dependencies are clean. Two critical
  advisories are in dev-only test tooling (vitest/tinypool).
- **Fix:**
  - Upgrade pypdf, python-multipart, FastAPI and Starlette, and
    python-dotenv.
  - Replace python-jose with PyJWT (the JWT code is about 20 lines).
  - Upgrade vitest.
  - Add `pip-audit` and `npm audit --omit=dev` to CI so this can't drift
    again.

**H3 — A full class asking at once will queue, then fail.**
- **Evidence:** `/tutor/message` keeps its database session (and
  connection) open while waiting for Claude. The pool is SQLAlchemy's
  default: 5 connections plus 10 overflow, so 15.
- **Measured:** 40 learners asking at once, with Claude taking only 5 s,
  saw a median 10.6 s wait and a slowest of 15.7 s. Real answers take
  10–30 s, so the last learners would wait over a minute or hit the
  30-second pool timeout.
- **Same pattern elsewhere:** assignment marking and parent-summary
  translation.
- **Fix:**
  - Commit and release the connection before calling Claude, then save the
    reply in a short new session.
  - Size the pool explicitly.
  - Re-run the 40-learner test as a regression test.

**H4 — No production basics yet** (GCP plan on hold).
- **Missing:** encrypted automated backups with a tested restore; error
  tracking and alerts (5xx rate, Claude failures, latency); HTTPS;
  security headers and CSP on the frontend; managed secrets; a staging
  copy; log retention.
- **Also:** `/docs` and `/openapi.json` are public. They should be off in
  production.
- **Fix:** make these part of the GCP plan's definition of done.

**H5 — Running cost is invisible and could be high.**
- **Evidence:** token usage from Claude responses isn't recorded anywhere.
- **Estimate:** the configured model is Sonnet 4.6 ($3 in / $15 out per
  million tokens; cached input $0.30). The tutor prompt is about 1,350
  tokens before textbook text, history (up to 20 messages) and page
  images. A typical question is roughly 3–8k tokens in and 400–800 out,
  so about **$0.015–0.035 (R0.30–R0.65)**.
- **What that means:** the 60-a-day limit allows about R20–40 per learner
  per day in the worst case.
- **Fix:**
  - Log input, output and cached tokens per call, with school and
    feature.
  - Add a cost view per school.
  - Consider per-school monthly budgets, a cheaper model for marking and
    translation (already configurable), shorter history, and a lower
    default limit until real usage is known.

### Medium

**M1 — POPIA gaps that aren't code.**
- Learners' messages and uploads go to Anthropic in the US. That's a
  cross-border transfer, which needs a data-processing agreement and a
  plain mention in the privacy notice (already an open item).
- There's no automatic retention or deletion: conversations, uploads,
  expired sign-up codes, used invites and audit events are kept forever.
  Agree retention periods, then add a nightly clean-up.
- Consent is recorded but not enforced. That's the pending policy
  decision.

**M2 — A classmate can lock someone out on purpose.**
- Five wrong passwords lock that login for 15 minutes, and learners know
  each other's student numbers.
- **Fix:** count failures per login *and* device or IP, or use a growing
  delay instead of a hard lock, and tell the learner the lock is
  temporary.

**M3 — Invite codes can be guessed without limit.**
- `/connect/viewer/redeem` has no rate limit. The codes carry about 40
  bits and expire in 7 days, so it's hard but not bounded.
- **Fix:** the same per-IP throttle as the SMS codes.

**M4 — Uploads.**
- There's no per-learner quota (disk can fill).
- The whole file is read into memory before its size is checked.
- The file type comes from the browser's header, not the file contents.
- **Fix:** stream with a size cap, check magic bytes, add a daily quota
  per learner, and parse PDFs with a timeout. That timeout matters more
  given H2.

**M5 — Test integrity.**
- During an open *test*, a learner can paste the question into the tutor
  and be talked through it.
- **Fix:** while a test is open for that learner, the tutor coaches
  without solving anything that matches a test question, and the teacher
  can see that the tutor was used.

**M6 — Data size on prepaid bundles.**
- One 1.2 MB JavaScript file (345 KB gzipped). Every learner also
  downloads TEACH, ADMIN and INSIGHTS code.
- At 1,200 learners, Today returns 342 KB and class progress 671 KB.
- **Fix:** split the bundle per product (lazy imports); trim and paginate
  Today and Progress; gzip/brotli at the edge.

**M7 — Untested permission areas.**
- The integration suite doesn't cover INSIGHTS, the dashboard API,
  books, uploads, Today, classes, roles and allocations, notices,
  consent, SMS sign-up verify, or viewer redeem.
- The code reviewed is scoped correctly, but untested scoping regresses
  silently.
- **Fix:** add these to `tests/integration`.

**M8 — AI-written content needs teacher review.**
- 245 practice questions added on 19 Nov, including all of chemistry.
  Their numeric answers are re-computed by a test, but wording and CAPS
  fit need a teacher.
- MathGuard checks algebra and arithmetic, not explanations or science
  facts.
- **Fix:** a review checklist per subject, plus a "reported by teacher"
  flag on questions.

### Low

| # | Finding | Fix |
|---|---|---|
| L1 | Login school picker fails axe (`listbox`/`option` roles on the wrong elements: 1 critical + 5 serious). | Put `role="option"` on the list items, or drop the roles. |
| L2 | Parent-summary translation cache grows forever (one entry per child, language and day). | Expire old days. |
| L3 | Unused tables: `video_resources`, `practicals`, `practical_runs`. | Remove in a migration, or document the plan. |
| L4 | `TeacherAdminScreen.jsx` 1,351 lines, `SchoolPanel.jsx` 993, `ChatScreen.jsx` 938. | Split by panel when next touched; add screen tests. |
| L5 | Deprecation warnings (Pydantic class-based `Config`; `utcnow` inside python-jose). | Goes away with H2 and a small schema tidy. |
| L6 | Throttles live in one server's memory. | Database or Redis when there's more than one server. |
| L7 | One AI model, no fallback. | Optional fallback model on overload errors. |
| L8 | Duplicate index on `learners.user_id` (unique plus plain). | Drop the plain one. |

## Recommended order

1. **Before any real learner (about 2–3 days of work):** H1 safeguarding
   prompt and red-team tests; H2 dependency upgrades and PyJWT, plus
   audits in CI; H3 connection release and a concurrency regression test;
   M2 lockout; M3 invite throttle; M4 upload hardening; L1.
2. **Before the pilot grows:** H5 token logging, a cost view and budgets;
   M5 test integrity; M6 code splitting and lighter payloads; M7 tests;
   M1 retention clean-up once periods are agreed.
3. **With the GCP deployment:** H4 in full, L6, L7.
4. **Needs people, not code:** safeguarding process with schools, an
   Anthropic data-processing agreement, retention periods, the consent
   policy, teacher review of content (M8), isiZulu Grades 11–12.
