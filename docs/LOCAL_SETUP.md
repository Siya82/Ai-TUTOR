# Local Development Setup

Every step below was run and verified in the original build session against a
real PostgreSQL 16 + pgvector database — not just described. Two bugs
were caught and fixed in the process (see the notes marked ⚠ below);
those fixes should already be in the recovered migration once rebuilt.

## 1. Software to install

| Software | Version | Purpose | Get it |
|---|---|---|---|
| **Python** | 3.12+ | Backend runtime | [python.org/downloads](https://www.python.org/downloads/) |
| **Docker Desktop** | latest | Runs Postgres+pgvector without native compilation | [docker.com/products/docker-desktop](https://www.docker.com/products/docker-desktop/) |
| **Git** | latest | Version control | [git-scm.com](https://git-scm.com/) |
| **VS Code** (or your editor of choice) | latest | Editing | [code.visualstudio.com](https://code.visualstudio.com/) |
| **Anthropic API key** | — | Live tutor calls | [console.anthropic.com](https://console.anthropic.com/) |

**On the database: use Docker, not a native Postgres install**, especially
on Windows. `pgvector` is a compiled Postgres extension — on Linux it's a
one-line `apt install`, but on Windows it means building from source with
Visual Studio's C++ toolchain, which is real friction for no benefit here.
The `pgvector/pgvector:pg16` Docker image already has it built in.

VS Code extensions worth adding: **Python** (Microsoft), **Pylance**, and
either the **PostgreSQL** extension (Chris Kolkman) or a standalone GUI
like **pgAdmin4** or **DBeaver** if you want to browse tables visually.

## 2. Get the project onto your machine

```
C:\dev\ai-caps-tutor          (Windows)
~/dev/ai-caps-tutor            (Mac/Linux)
```

(On the new machine, initialize `git init` here immediately and push to a
private GitHub remote before writing any further code — see the recovery
notes in REBUILD_SPEC.md.)

## 3. Start the database

From the project root:

```bash
docker compose up -d
```

This starts Postgres 16 with pgvector already installed, on
`localhost:5432`, with a persistent volume — your data survives restarts
unless you explicitly run `docker compose down -v`.

Confirm it's running:

```bash
docker compose ps
```

## 4. Set up the backend

```bash
cd backend
python3 -m venv .venv

# Activate it:
.venv\Scripts\activate        # Windows
source .venv/bin/activate     # Mac/Linux

pip install -r requirements.txt
```

Copy the environment file and fill in your real API key:

```bash
cp .env.example .env          # Mac/Linux
copy .env.example .env        # Windows
```

Edit `.env`:
```
DATABASE_URL=postgresql+asyncpg://postgres:postgres@localhost:5432/caps_tutor
ANTHROPIC_API_KEY=sk-ant-...           # your real key from console.anthropic.com
ANTHROPIC_MODEL=claude-sonnet-4-6
ENVIRONMENT=development
CORS_ORIGINS=["http://localhost:5173"]
```

## 5. Run the database migration

This creates all application tables (and enables the `vector` extension
automatically — that fix must be baked into the migration file, see
note ⚠1 below):

```bash
alembic upgrade head
```

Verify it worked:

```bash
docker exec -it $(docker compose ps -q db) psql -U postgres -d caps_tutor -c "\dt"
```

## 6. Run the API

```bash
uvicorn app.main:app --reload
```

Visit `http://localhost:8000/health` — you should see:
```json
{"status": "ok", "environment": "development"}
```

Interactive API docs (auto-generated by FastAPI) are at
`http://localhost:8000/docs`.

## Bugs already fixed once (re-check for these on a rebuild)

**⚠1 — pgvector migration needs two manual fixes.** Alembic's
autogenerate produced a migration referencing `pgvector.sqlalchemy.vector.
VECTOR` without importing `pgvector`, and didn't include `CREATE EXTENSION
vector` — meaning it would fail on any database where the extension
hadn't already been manually enabled. Both must be fixed directly in the
generated migration. Check for both issues again on any migration
touching `content_chunks`.

**⚠2 — Alembic needs the sync driver, the app needs the async one.**
`migrations/env.py` should automatically swap `+asyncpg` for `+psycopg2`
from a single `DATABASE_URL` — don't maintain two separate connection
strings.

**⚠3 (added after the original build, per project memory) — Windows
asyncpg + NullPool.** `conftest.py` needs to enforce
`WindowsSelectorEventLoopPolicy` on Windows, and `database.py` needs a
`sys.modules` check to scope `NullPool` to pytest specifically.

**⚠4 — PowerShell `Out-File` BOM corruption.** Use
`[System.IO.File]::WriteAllText` with `[System.Text.UTF8Encoding]::new($false)`
instead of `Out-File` when writing files from PowerShell scripts.
